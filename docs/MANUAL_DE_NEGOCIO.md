# MANUAL DE FUNCIONAMIENTO DE LA APP AK PRODUCCIONES

VERSIÓN PARA IA / AGENTE DE DESARROLLO

## OBJETIVO

Esta app es un sistema integral para gestión comercial y operativa de fiestas y eventos.  
La IA debe entender la lógica del negocio antes de tocar código.

## REGLA GENERAL

No asumir que la app es un conjunto de pantallas aisladas.  
La app funciona como un flujo comercial y operativo completo.

## FLUJO PRINCIPAL DEL NEGOCIO

1. Entra un contacto o lead
2. Se registra en CRM o clientes
3. Se crea o construye un presupuesto
4. Se confirma la contratación
5. Se crea / vincula la fiesta o evento
6. Se prepara la experiencia del evento
7. Se gestionan pagos, contrato, WhatsApp, portal, decoración y operación interna

LA APP NO SE DEBE PENSAR SOLO POR MÓDULOS.  
SE DEBE PENSAR POR FLUJOS.

## 1. MÓDULOS PRINCIPALES

### 1. INICIO / DASHBOARD
Función:
- mostrar resumen general del negocio
- accesos rápidos
- alertas
- entradas a módulos más usados

Debe permitir:
- navegar rápido
- ver pendientes
- detectar problemas
- abrir módulos principales

### 2. PRESUPUESTOS
Función:
- crear presupuestos manuales
- editarlos
- agregar / quitar servicios
- recalcular importes
- imprimir / enviar / convertir

Es uno de los módulos más críticos.  
Todo lo comercial depende de que este módulo funcione bien.

Debe estar conectado con:
- clientes
- CRM
- eventos
- presentación / catálogo
- pagos

### 3. CLIENTES
Función:
- alta y edición de clientes
- datos de contacto
- historial
- relación con presupuestos y fiestas

Debe servir como ficha base de la persona contratante o cliente final.

### 4. CRM / PROSPECTOS
Función:
- registrar leads o interesados
- moverlos por etapas
- hacer seguimiento
- convertirlos a cliente o presupuesto

Debe ser un tablero de seguimiento comercial, no una base de basura.  
No debe aceptar leads mínimos o inválidos sin control.

### 5. FIESTAS / EVENTOS
Función:
- crear y gestionar el evento real
- fecha
- salón
- invitados
- servicios asociados
- relación con cliente y presupuesto

El evento es la entidad operativa final.

### 6. PRESENTACIÓN LED / CATÁLOGO DIGITAL
Función:
- vender servicios visualmente
- mostrar fotos, bloques, categorías y opciones
- permitir elegir servicios
- alimentar el presupuesto manual en paralelo

IMPORTANTE:  
No debe existir lógica duplicada innecesaria.  
La presentación y el catálogo deben compartir la misma lógica comercial y la misma estructura de datos.

### 7. PÁGINA DEL EVENTO / INVITACIÓN / PORTALES
Función:
- mostrar información del evento al cliente o invitados
- ubicación
- regalo o dinero
- dress code
- fotos
- portal social si aplica

Debe estar sincronizado con la fiesta real.

### 8. DECORACIÓN
Función:
- planificar visualmente la decoración
- mover elementos
- ordenar capas
- colores
- escalado
- composición visual

Debe sentirse como editor visual, no como lista rígida.

### 9. WHATSAPP / MARKETING / AUTOMATIZACIONES
Función:
- plantillas
- mensajes
- automatizaciones
- seguimiento comercial

Debe conectarse con:
- CRM
- presupuestos
- clientes

### 10. INVENTARIO / SERVICIOS / PROVEEDORES / INSUMOS
Función:
- contener el catálogo real de lo que vende la empresa
- servicios
- paquetes
- insumos
- proveedores
- configuraciones del simulador

Esto es base del negocio.  
No se debe perder ni vaciar silenciosamente.

### 11. PAGOS / CONTABILIDAD / FACTURAS
Función:
- registrar pagos
- plan de pagos
- controlar estados
- facturas
- seguimiento financiero

### 12. CONFIGURACIÓN / BACKUPS
Función:
- ajustes generales
- plantillas
- configuraciones del sistema
- respaldos
- restauración

## 2. LÓGICA COMERCIAL DE VENTA VISUAL

La app tiene una parte de venta interactiva visual.  
No es solo una landing.  
Debe construir presupuesto real.

La lógica correcta es:

### A. PARTE COMÚN
- portada
- presentación de empresa
- quiénes somos
- por qué elegirnos
- testimonios / confianza
- salón
- datos del evento

### B. DESPUÉS SE ELIGE TIPO DE FIESTA
- XV años
- bodas
- cumpleaños
- infantiles
- empresariales
- otros

### C. LUEGO ENTRA EL CATÁLOGO ESPECÍFICO
Pero con una regla:
- el formato es el mismo
- las categorías son las mismas
- los servicios son los mismos
- lo que cambia son las fotos y la ambientación visual

### D. MIENTRAS EL CLIENTE ELIGE
Se debe ir armando el presupuesto manual real.

NO debe haber:
- una presentación por un lado
- y un presupuesto totalmente separado por otro

La selección comercial debe alimentar el presupuesto.

## 3. ORDEN COMERCIAL DEL CATÁLOGO / PRESENTACIÓN

El orden correcto de la experiencia de venta es:
1. Portada
2. Quiénes somos
3. Por qué elegirnos
4. Testimonios / empresas / confianza
5. Datos del evento
6. Fecha deseada
7. Disponibilidad / fechas cercanas si está ocupado
8. Salón
9. Tipo de fiesta
10. Catering
11. Decoración
12. Discoteca
13. Fotografía
14. Filmación
15. Belleza / maquillaje / uñas
16. Entretenimiento / extras
17. Barra
18. Regalos / dinero / cuenta si aplica
19. Resumen final
20. Presupuesto manual
21. Envío
22. Plan de pagos
23. Contrato

## 4. REGLAS IMPORTANTES PARA LA IA

1. NO DUPLICAR MÓDULOS
Si hay dos módulos que hacen casi lo mismo, la IA debe intentar unificar lógica.
Ejemplo:
- presentación LED
- catálogo por tipo de fiesta
No deben vivir como sistemas paralelos si comparten lógica de negocio.

2. NO ROMPER LA SINCRONIZACIÓN
Presupuesto, cliente, CRM, evento y presentación deben estar conectados.
No crear estructuras de datos incompatibles entre sí.

3. NO CREAR ÉXITOS FALSOS
Si una acción no fue confirmada, no debe mostrarse como exitosa.
La app no debe mentir.

4. NO DEJAR DATOS VACÍOS SILENCIOSAMENTE
Si falta información crítica, el sistema debe mostrarlo claro.
No debe parecer que “no hay nada” si en realidad hubo un problema de lectura o guardado.

5. NO TOCAR AUTH SI NO LO PIDEN
El tema de login/contraseña/auth está cerrado salvo pedido explícito.
No usar eso como excusa para tocar código no relacionado.

6. NO REHACER TODO DESDE CERO
La app ya tiene mucha base construida.
La IA debe reutilizar lo existente y estabilizar, no reinventar sin necesidad.

## 5. CÓMO DEBE FUNCIONAR CADA RELACIÓN

CLIENTE
- puede tener uno o varios presupuestos
- puede estar vinculado a un evento
- puede venir desde CRM

CRM
- puede generar cliente
- puede generar presupuesto
- debe servir para seguimiento

PRESUPUESTO
- puede nacer manualmente
- puede nacer desde presentación/catálogo
- debe vincularse a cliente y evento
- puede pasar a contratación

EVENTO
- debe vincularse con cliente y presupuesto
- debe alimentar página del evento y experiencia final

PRESENTACIÓN / CATÁLOGO
- debe vender visualmente
- debe seleccionar servicios
- debe construir presupuesto

DECORACIÓN
- debe trabajar sobre el evento o la propuesta visual del evento

WHATSAPP
- debe apoyar CRM, cliente y presupuesto
- no vivir aislado como solo “settings”

## 6. MÓDULOS QUE NO DEBEN ROMPERSE

Críticos:
- Presupuestos
- Clientes
- CRM
- Eventos
- Servicios / inventario / proveedores / insumos

Muy importantes:
- Presentación / catálogo
- Dashboard
- Alertas
- Página del evento
- WhatsApp

Secundarios pero relevantes:
- Decoración
- Empleados
- Marketing
- Backups
- Analytics

## 7. ERRORES QUE LA IA DEBE SABER EVITAR

- crear presupuesto y no guardarlo realmente
- borrar en UI pero que vuelva al refrescar
- desincronizar planificador y presupuesto manual
- aceptar leads basura en CRM
- dejar módulos vacíos por fallos silenciosos de datos
- dejar la voz del asistente solo como transcripción pasiva
- duplicar lógica entre presentación y catálogo
- crear landings lindas pero desconectadas del presupuesto real
- tocar seguridad cuando el problema es de negocio o integración

## 8. OBJETIVO TÉCNICO GENERAL

La IA debe priorizar:
1. estabilidad
2. coherencia entre módulos
3. guardado real
4. mensajes claros
5. experiencia comercial usable
6. reutilización del código existente

No priorizar:
- nuevos módulos grandes
- cambios cosméticos aislados
- complejidad innecesaria
- “parches” que no resuelven la base

## 9. OBJETIVO FINAL DE LA APP

La app debe permitir que AK Producciones:
- capte contactos
- haga seguimiento comercial
- venda visualmente
- construya presupuestos
- confirme contrataciones
- gestione eventos
- opere decoración, servicios y proveedores
- cobre y cierre correctamente

Si un cambio no mejora uno de esos puntos, probablemente no sea prioritario.
